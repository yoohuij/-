# Discord 반응 인원 체크 봇

특정 메시지의 이모지 반응을 기준으로, 아직 반응하지 않은 서버 구성원을 찾는 봇입니다. 결과 목록은 멘션을 보내지 않으며, `미반응자 멘션` 버튼을 눌렀을 때만 실제 알림이 전송됩니다.

## 준비

1. [Discord Developer Portal](https://discord.com/developers/applications)에서 애플리케이션과 봇을 만듭니다.
2. **Bot → Privileged Gateway Intents**에서 **Server Members Intent**를 켭니다.
3. OAuth2 URL Generator에서 `bot`, `applications.commands` 범위를 고르고 서버에 초대합니다.
4. 봇 역할에 다음 권한을 부여합니다.
   - 채널 보기, 메시지 기록 보기, 메시지 보내기
   - 반응 보기
   - 멤버 목록 접근
5. `.env.example`을 복사해 `.env`로 이름을 바꾸고 봇 토큰을 넣습니다.

## 실행

Python 3.14.7 환경에서 아래 순서로 실행합니다.

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -U pip
pip install -r requirements.txt
python bot.py
```

`py -3.14`가 인식되지 않으면 Python 3.14.7을 설치한 뒤 다시 실행하세요.

## 사용법

1. 확인할 메시지를 **같은 채널**에 보냅니다.
2. Discord 설정의 고급 메뉴에서 개발자 모드를 켠 뒤, 메시지를 우클릭해 **메시지 ID 복사**를 선택합니다.
3. 관리자가 다음을 실행합니다.

```text
/인원체크 message_id:복사한_ID emoji:✅
```

`emoji`는 필수이며, 지정한 이모지로 반응한 사용자만 반응자로 봅니다. 이 명령은 서버당 하나의 대상 메시지를 저장하며, 다시 실행하면 대상이 교체됩니다.

등록 정보는 봇 폴더의 `attendance.sqlite3` 파일에 저장됩니다. 봇을 재시작해도 유지되므로 이 파일을 삭제하지 마세요. 단, 무료 호스팅처럼 재시작 때 파일 시스템이 초기화되는 환경에서는 데이터베이스 파일이 사라질 수 있으니 영구 디스크를 연결하거나 외부 데이터베이스를 사용해야 합니다.

4. 확인할 때는 다음을 실행합니다.

```text
/미반응자 확인
```

결과 메시지는 명령 실행자에게만 보이며, 목록에서는 누구도 멘션되지 않습니다. 버튼으로 페이지를 넘기거나 새로고침할 수 있습니다. `미반응자 멘션`은 명령 실행자 또는 서버 관리 권한자만 누를 수 있고, 실제 멘션은 현재 채널로 전송됩니다.

## DM 공지

서버 관리 권한이 있는 사용자는 다음 명령어로 모든 일반 유저에게 공지를 보낼 수 있습니다.

```text
/공지 내용:공지할 내용
```

DM은 아래 형식으로 전송됩니다.

```text
# [외지주 공지]

공지할 내용

-# 공지 DM입니다 @수신자
```

봇과 DM을 차단한 사용자, 이미 서버에서 나간 사용자는 건너뜁니다. 전송 완료 후 명령 실행자에게만 전체·성공·실패 인원과 실패 인원 멘션 목록이 표시됩니다. 이 목록의 멘션은 보기용이며 실패한 사용자에게 알림을 보내지 않습니다. Discord 전송 제한을 준수하기 위해 대규모 서버에서는 완료까지 시간이 걸릴 수 있습니다.

## 공지 예외 인원

특정 유저에게 공지 DM을 보내지 않으려면 다음 명령어를 사용합니다.

```text
/공지예외인원설정 유저:@유저 동작:추가
```

해제할 때는 `동작:제거`를 선택합니다. 공지 예외 설정은 서버별로 저장되며, `/공지` 전송 결과에 제외 인원 수가 함께 표시됩니다.

## 참고

- 봇은 현재 서버에 남아 있는 일반 유저만 비교합니다. 봇 계정은 제외합니다.
- 서버 구성원이 매우 많은 경우 Discord 조회 제한 때문에 결과 생성에 약간 시간이 걸릴 수 있습니다.
- 반응자는 기본적으로 선택한 이모지 하나로 판단합니다. 여러 이모지 중 하나로 인정하는 규칙이 필요하면 다음 단계에서 확장할 수 있습니다.

## Railway 배포

1. 이 폴더를 GitHub의 새 **비공개 저장소**에 올립니다. `.env`는 올리지 않습니다.
2. Railway에서 **New Project → Deploy from GitHub Repo**를 선택하고 저장소를 연결합니다.
3. 서비스의 **Variables** 탭에서 `DISCORD_TOKEN`에 봇 토큰을 입력합니다.
4. 서비스 **Settings**에서 Start Command를 `python bot.py`로 설정합니다.
5. 서비스에 Volume을 추가하고 Mount Path를 `/data`로 설정합니다.
6. Variables 탭에서 `DATABASE_PATH`를 `/data/attendance.sqlite3`로 추가하고 배포합니다.

Volume을 연결하지 않으면 배포나 재시작 때 인원 체크·공지 예외 설정이 초기화될 수 있습니다.
